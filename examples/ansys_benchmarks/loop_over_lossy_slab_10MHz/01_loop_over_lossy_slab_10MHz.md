# `-e ans:1` — loop over a lossy slab at 10 MHz: our half of the AED benchmark

Guide for
`examples/ansys_benchmarks/loop_over_lossy_slab_10MHz/01_loop_over_lossy_slab_10MHz.py`.
Written to be followed without the source open.

**Read `SPEC.md` and `COMPARISON.md` in this directory alongside this guide.**
They are not duplicated here, on purpose:

- **`SPEC.md` is the authority** for geometry, materials, boundary conditions,
  excitation, frequency, mesh guidance, the export list and the reference
  values. It is the document the human operator replicates in Ansys Electronics
  Desktop. If this guide and `SPEC.md` ever disagree about the problem,
  `SPEC.md` wins.
- **`COMPARISON.md` is the result**, and it is **regenerated by every run** —
  our column and the closed-form column are both produced by the run that wrote
  it, and the AED columns are left blank for the operator. Never hand-edit it
  except to fill the AED columns.

This guide covers only what neither of those says: how to run the script and how
to read its output.

## 1. What this demonstrates

**The first commissioned Ansys benchmark — our half of a like-for-like
comparison.** `ANS-1` (✅ 2026-08-09) exists so that a number this project gates
can be put next to the same number from a commercial solver, computed from a
written specification rather than from a shared file. The comparison is the
point; this script is one of its two halves.

The physics is `MAT-6`'s and is **imported, not restated**: the constants, the
mesh, the azimuthal drive and `_solve_projected` all come from
`tests/validation/test_dodd_deeds_impedance.py` and
`tests/validation/test_dodd_deeds_projected_drive.py`, and the assembled compute
path is shared directly with the `EX-11` example
(`examples/materials/01_dodd_deeds_coil_loading.py`) rather than duplicated. So
the benchmark cannot drift away from the landed gate — read that example's guide
first if you want the physics of coil loading explained; this one assumes it.

What this script adds over `mat:1`:

- **Per-solve terminal `R` and `X`**, not just their difference. `SPEC.md`'s
  export table asks for `R` and `X` at the coil terminals for both solves, so
  the reaction integral is taken per solve; their difference is algebraically
  the ΔZ the gate asserts.
- **A second anchor leg: the fixture-identity pin.** ΔR must land within
  **1e-3 relative** of `+3.2770406e-01 Ω` — the value `EX-11` reproduced digit
  for digit on 2026-08-09. The first leg (2% against the closed form) says we
  got the right *answer*; the pin says we solved the *same problem the gate
  solved*, not merely one with the same closed-form answer.
- **The operator-facing deliverables**: `metrics.json`, `COMPARISON.md`, and the
  |J| field export.

**10 MHz, eddy-current regime — no Larmor claim.** The case is commissioned in
the regime where our number is gated, on purpose. PROJECT_PLAN §2.1 is explicit
that the saline/Larmor case is an extrapolation, not a result.

On record at `-n 2` (`20260809T183731Z_ANS-1.log`, exit 0, **70 s**
harness-wall / 68.4 s in-script, 2026-08-09 13:30 slot; 138 619 cells meshed in
11.0 s, solves 28.4 s loaded + 26.8 s free — matching `EX-11`'s 74 s for the
same path):

| Quantity | Value | Bound |
| --- | --- | --- |
| ΔR vs Dodd–Deeds (+3.2259615e-01 Ω, regenerated at run time) | **1.5834%** | 2% |
| ΔR vs the pinned +3.2770406e-01 Ω | **1.387e-08** relative | 1e-3 |
| ΔR sign | **+** (a conductor dissipates) | asserted |
| ΔX sign | **−** (induced currents expel flux) | asserted |

| max \|J\|, σ = 0 control | **0.0** A/m² | `== 0.0`, no tolerance |

The gate of record is `MAT-6` step 3. The 2% ceiling is the example's, not the
gate's (the gate's own is 5%); it is what this fixture delivers and it is **not
a knob** — a miss is a regression finding.

## 2. How to run it

```
./run_examples.sh -e ans:1 -n 2 -t 180
```

**Complex build required** — the `ans:` group sources it automatically (one case
directory per benchmark), and a real build raises. Tier: **standard**; 70 s
harness-wall on record, of which 11.0 s is meshing and 55.2 s is the two solves.

Each run rewrites `metrics.json` and `COMPARISON.md` in this directory and
regenerates `paraview_output/ans1_loop_over_lossy_slab_combined.xdmf` (untracked,
like every `paraview_output/` in the repo).

## 3. How to analyze it, step by step

**Step 1 — both legs of the anchor, in the console output.**

```
  [ΔR]  relative error 1.5834% against the 2% ceiling
  [ΔR]  against the pinned +3.2770406e-01 Ω: 1.387e-08 relative, ceiling 1e-3
```

Leg one is physics: we match the closed form. Leg two is identity: we match the
gate's own number to eight decimal places, which no independent implementation
would do by accident. Leg two is the one that matters for a *benchmark* — a
published comparison must be traceable to the specific gated computation, not to
a re-derivation that happens to agree. A drift on leg two at matched fixture is a
regression finding: stop, report, and do not publish against a moved number.

**Step 2 — the per-solve `R` and `X` rows, which are reported and not gated.**

```
  [Z]  σ=100: ... + j(...) Ω
  [Z]  σ=0  : ... + j(...) Ω   — R here is a numerical zero; both rows reported, never gated
```

The reaction integral gates the **difference**; each solve's own `R` and `X`
carry the finite-box truncation and are not converged quantities. They are in
the output because `SPEC.md`'s export table asks for them, and because the σ = 0
solve's `R` being a numerical zero against a finite `X` is itself informative —
printed so its size is visible rather than hidden inside a subtraction. When the
AED columns are filled, expect the absolute rows to agree less well than ΔR;
that is expected and is not the adjudication.

**Step 3 — ΔX, the row the case was actually commissioned for.**

```
  [ΔX]  ratio 0.9200 — reported, never gated: not converged in box size
        (`MAT-6` step 4). This row is why the case was commissioned.
```

ΔX is 8% low against Dodd–Deeds because it is **not converged in box size**:
`MAT-6` step 4 measured 5.57% still moving between `W = 0.15` and `W = 0.20`.
The reactive term samples the field far from the loop, where a finite PEC box
truncates it; ΔR converges much faster because dissipation is local to the skin
layer. An independent commercial solver's ΔX on the same specified box is
therefore a genuine adjudication input — it tells us whether the residual is box
truncation (both solvers should show it) or something in our formulation (only
ours would).

**Step 4 — the negative control, in-fixture and exact.**

```
  [control] ohmic power in the slab: loaded 1.385836e-01 W, free 0.000000e+00 W
  [paraview] max |J| = 6.84e+02 A/m² loaded, 0.000000e+00 A/m² in the control
```

The σ = 0 solve is the free half of the same pair, so it shares the mesh, the
drive and every constant. Both control values are asserted `== 0.0` with **no
tolerance**: with σ identically zero cell by cell the integrand is zero cell by
cell. Total separation.

The energy cross-check on the adjacent line — ½ΔR|I′|² from the reaction
integral against `∫_slab (σ/2)|E|² dV` from the solved field, **ratio 1.0000** —
is analytically equivalent to the extraction, so it is reported and not gated. A
ratio away from 1.0000 would mean the extraction path and the field disagree
about where the power went, and neither ΔR nor the picture should be trusted.

**Step 5 — read `COMPARISON.md`, which the run just rewrote.** Its
"Terminal quantities" table is the deliverable. Check three things:

1. The **ΔR row** is bolded and carries both tolerances — that is the gated row.
2. The **closed-form column** was regenerated from
   `src/fem_em_solver/utils/dodd_deeds.py` at run time, not transcribed. The
   "Provenance" section at the bottom names the exact call.
3. The **AED columns are blank**. Filling them is the operator's half; report
   *all* digits AED prints, and do not round to ours.

`metrics.json` carries the same content machine-readably, plus `n_cells`,
`mpi_ranks`, the mesh sizing block, per-solve `solve_seconds`, and
`"aed": null` — the slot the operator's numbers go into.

**Step 6 — open the field export in ParaView.**
`File → Open → examples/ansys_benchmarks/loop_over_lossy_slab_10MHz/paraview_output/ans1_loop_over_lossy_slab_combined.xdmf`,
then colour by `J_magnitude` (A/m²).

1. **Threshold** on `CellTags` — `3` is the lossy slab, `1` is the wire. Keep
   tag 3.
2. **What to look at:** an annular bright band on the slab's top surface under
   the loop, decaying downward over the printed skin depth
   δ = 1/√(πfμ₀σ) ≈ 1.59 mm ≈ 0.032 a. Peak should be the printed
   `max |J| = 6.84e+02` A/m².
3. **For the AED half:** export the current-density magnitude on the **same
   cut** so the spatial distributions can be compared, not only the terminal
   numbers. Two solvers can agree on ΔR while disagreeing about where the
   current flows, and that disagreement is worth catching.

**Step 7 — what a deviation means.** ΔR outside 2% → a regression against
`MAT-6` step 3; report both numbers and stop. ΔR inside 2% but outside 1e-3 of
the pin → the fixture has moved (mesh sizing, drive, box) even though the physics
still lands; the benchmark is no longer solving the gate's problem and must not
be published until that is understood. ΔR near zero → the slab's σ is not
reaching the assembly; compare against the σ = 0 control, which is that exact
failure. ΔR negative → the loaded and free solves are swapped. Energy ratio away
from 1.0000 → extraction and field disagree. Control power or control `max |J|`
not exactly `0.0` → the σ field is not identically zero outside the slab and
every number above is suspect. Cell count away from 138 619 → the mesh changed
and this record does not apply; `SPEC.md`'s mesh guidance is what the AED half
was sized against.
